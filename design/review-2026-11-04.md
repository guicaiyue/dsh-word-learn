## 1. 必修（数据正确性）

### 1.1 R5 自我续期（高）`lib/r5.mjs:130-154`
候选条件「昨天任意 stage 有 repair_log」把 R5 自己昨天写的 `stage='tomorrow'` 也算作「昨天有活动」，
排除又只看**今天**的 tomorrow 日志 → 任何进过回访的词此后**每天必出题**，答对也不终止
（无债时 `cleared=false`，没有任何状态能把它移出候选）。`scripts/test-r5.mjs:242-247` 的 match 用例
把这个循环固化成了预期，修候选条件时必须同步改断言。

**改法**：候选只认补记类活动 `stage IN ('pick','spell','session_end')` 或债务 `opened_at` 落在昨天；
对 `stage='tomorrow'` 追加「仍有未清债 或 最近一次 tomorrow 的 `ok<>1`」。
终止条件 = 债已清 且 昨天那次答对。

### 1.2 答对时无条件清债（中）`lib/r5.mjs:353-359`
`clearRepairDebt(wordId)` 不校验 `opened_at`。若该词今天在主队列又评了 Again（`openRepairDebt` 把
`opened_at` 重置为今天），R5 仍因昨天的日志把它当候选，答对时会把**今天刚开的债**静默销掉 —— 绕过 R3/R4。
**改法**：按 `opened_at < dayStart(0, now)` 上界清债；今天开的债只记日志。

### 1.3 submitRecap 无事务/无幂等（中）`lib/r5.mjs:336-363`
双击/重试/双开标签 → 两条 tomorrow 日志；答错时 `opened_at` 二次刷新、`tries` 归零；
`logRepair` 失败（只返回 false）后仍会清债/开债 → 状态变了却没有审计记录。
**改法**：`BEGIN IMMEDIATE`/`COMMIT` 包住；同 `wordId+cardId` 当天已有 tomorrow 日志时只更新；`logRepair` 失败即返回。

### 1.4 写库失败被吞成 ok:true（高）`lib/index.js:275` + `lib/store.mjs:269`
`Store.touch()` 在 `open()` 失败时返回 `{error}`，`lookupWord` 只读 `isNew`，`error` 被丢；
随后 `store.get()` 返回 null → 响应 `ok:true, saved:null`，前端当 `{}` 渲染。
**用户以为在攒生词本，实际一条没存。** 同理 `setMeta` / `logRepair` 的 false 也没人看。
**改法**：响应体带 `warnings`（或 `savedError`），前端显式提示一次"未保存：原因"。

### 1.5 store.open() 一次失败即永久熔断（高）`lib/store.mjs:242-256`
`this.error` 一旦置上就不再重试，`close()` 也不清 → 一次瞬时 `SQLITE_BUSY` 之后本进程所有读写全 500，只能重启宿主。
**改法**：`close()` 清 error；open 失败记录 `errorAt`，允许按时间窗重试。

### 1.6 评分已提交却回 500（高）`lib/index.js:714-728`
`applyGrade()` 已写库，紧接着 `store.openRepairDebt(cardId)` 抛错被 catch → 500 → 客户端重试 → **同一张卡评两次**，FSRS 不可逆。
**改法**：主写入成功后立即 200，收尾副作用（记债）放 `try{}catch{}` 只记日志。

## 2. 必修（前端稳定性）

### 2.1 标注标到 800 个后永久停摆（高）`assets/annotate.js:656/689/717`
`state.spanCount` 只加不减，只有 `clearAnnotations()` 归零；React 重渲染/虚拟列表卸载的 span 不回退。
到 `GLOBAL_MAX` 后 `annotateBlock` 第一行直接 return —— 用户看到"标着标着全没了"。
**改法**：实时计数（`querySelectorAll('.dwl-anno').length`）或 `WeakMap<block,count>`；指纹里加 span 数。

### 2.2 改 React 拥有的文本节点（高）`assets/annotate.js:632-647/706-711`
`replaceChild` 换掉 React 的文本节点、`unwrapSpan` 又 `normalize()`：
React 再 `commitTextUpdate` 会写进已脱离文档的 node（文本冻结），`removeChild/insertBefore` 可能 `NotFoundError`。
**短期**：去掉 `normalize()`，运行中/未定稿块不标；**长期**：改 CSS Custom Highlight API（`CSS.highlights` + Range，零 DOM 变更）。

### 2.3 每 250ms 全量 scan（高）`assets/annotate.js:1227-1233/815-845`
我们自己插 span 的 childList 也会进 observer → 250ms 后全量 scan；scan 对每个已标块做 `textContent` + 4 次
`querySelectorAll`。209 块长会话下成本线性涨。`isBlocked` 还对每个文本节点 `matches()` 30+ 条选择器。
**改法**：mutation 回调维护 dirty 集合、忽略 `.dwl-anno` 内的变更；黑名单按容器判一次。

### 2.4 稳定窗定时器不清理（中）`assets/annotate.js:759-771`
流式期间每块能堆上百个 840ms timer，`stop()` 一个都不清。
**改法**：`WeakMap<block,timer>` 每块单例，`stop()` 统一清。

### 2.5 其它（中/低）
- `isActiveTail`/`hasRunningIndicator` 每次调用做全文档查询 → 每轮只算一次（`annotate.js:562-580`）。
- `attributeFilter` 漏 `data-chat-running` → 回合结束时最后一块可能长期不标（`:1266`）。
- 悬停卡 fetch 无超时/abort，悬挂时按钮永久 disabled（`:1088-1127`）。
- 卡片跟随滚动读-写-读强制布局 → rAF 合并 + `transform`（`:1184-1188`）。
- `tokenize` 只认 ASCII → `résumé` 被切成 `sum` 误标；撇号 `’`/`'` 不归一（`:169-201/324`）。
- `stats()` 的 blocks 与 spans 查了同一个选择器（`:413-422`）。

## 5. 交互设计建议（按用户习惯，未实施）

前提：成年开发者、每天 5–10 分钟、注意力很贵。判断标准是"打开就能开始、不用想、不被打断"。

**进入**
1. 昨日回访现在是**拦截页**，打开学习页先被考昨天的词。建议改成主队列前置的一张热身卡
   （有题才插，顶栏「昨天 3 个词，30 秒 · 跳过」），或只在距上次学习 >6h 的首次进入时触发。
2. 空态「今天没有到期的词」是死路，补「明天有 N 个到期 · 现在可以查词收词」。

**进行**
3. 快捷键 1/2/3/8/J 不可发现（只在灰字里）。首次进入弹一次 coach mark，7 天后或连续 5 次全鼠标操作重弹。
4. 「忘了」三步（义项四选一 → 对照 → 拼写）没有步进提示，加「第 1/3 步」，每步可跳过。
5. 评分后自动聚焦下一张主按钮；空格＝继续。
6. 标注悬停卡：300ms 延迟弹、卡片与词之间留桥接区、Esc/点外部关闭、触屏点击固定 —— 否则阅读中被反复打断。
7. 「收进复习」要可撤销：就地变「已收 ✓ · 撤销」，5 秒内可撤（`/remove` 已有）。
8. 标注开关要能被发现：设置里一个「对话内标注（开/关）」，现在只能改 localStorage。
9. 标注密度给「少/中」两档：少 = 只标今天到期 + 最近 3 天加的词。
10. 划词卡与标注卡行为要一致：都已补黑名单；开关/失败提示仍只有标注卡有。

**结束 / 事后**
11. 结束时一张战报：学了 N、忘了 M、明天到期 K + 「补记没记住的 3 个」入口。
12. 词汇页加筛选（未毕业 / 今天到期 / 最近加入）与排序（遗忘次数）。

## 7. 发音不可用：根因与修复（2026-11-05）

> **2026-11-05 后续：本节方案已被推翻，整段服务端发音下线。** 用户明确"单词都是前端用户操作触发的、前端反复使用，不需要有道之类的外部 API，只用浏览器自带的免费语音"——服务端拉取/落盘/坏缓存/浏览器 HTTP 缓存这一整类问题因此消失：`lib/tts.mjs`、`GET /tts`、`POST /tts-prepare`、学习页预取链路全部删除，改由 `assets/voice.js` 用 `speechSynthesis` 在本机合成（零网络、离线可用）。下面这段保留为"为什么走回头路"的过程记录，也是以后别再引入外部发音源的依据。



现象：用户反馈"有些单词无法发声"，怀疑 Edge 免费语音失效。

### 根因（两条，互相独立）

1. **缓存里有一个 8 字节的坏 mp3（`cache/tts/us/daemon.mp3`）**。
   - 来源：`scripts/test-routes.mjs` 在隔离前用真实 DSH_HOME 跑过，写过一个假音频（帧头 + 3 个填充字节），正是库里那条。
   - 为什么永久坏：`cachedAudio()` 只判 `size > 0` 就命中 → 路由每次原样返回 8 字节 + `Cache-Control: immutable`，浏览器解码失败，这个词永久没声音。
2. **有道免费源对部分词返回 500**（技术标识符如 `getuser`、带下划线的 `api_key`、部分词组的美音），旧逻辑只试一次就 503 → 前端退回 `speechSynthesis`；而 Edge/Chrome 的 `getVoices()` 首次异步为空，旧代码不等待就 `speak()`，部分环境直接静默失败 —— 这才是"Edge 免费语音像失效了"的观感来源。
   实测：`getUser` 两个口音都 500；`two words` 美音 500 但英音 200；`api key`（空格）两个口音都 200。

### 修复

- `lib/tts.mjs`
  - `MIN_AUDIO_BYTES=1024` + 文件头校验；不合法的缓存直接删掉重拉（自愈）。
  - `normalizeSpoken()`：允许词组（≤4 词 / 48 字符）、去变音符号、下划线当空格 —— 解决 `api_key`、`résumé`、`two words`。
