# 提示词模板：修一个 bug（含回归）

## 适用场景

用户报告"某个行为不对"：卡片不弹、学习页数据不对、发音没声、评分后间隔不对、报错。
不适用于新功能（用 `add-route.md` / `edit-frontend.md`）。
不确定是 bug 还是设计如此时，先查 `DESIGN.md` §9，再决定要不要改。

## 先读什么（别跳）

| 文件                   | 行区                                      | 为什么                                   |
| ---------------------- | ----------------------------------------- | ---------------------------------------- |
| 症状所在文件的开头注释 | 1–40                                      | 每个文件头都写了它为什么存在、踩过什么坑 |
| `README.md`            | 功能清单 19–95、接口表 115–135            | 确认"正确行为"是什么                     |
| `DESIGN.md`            | §9 待定/风险 655–778                      | 同症状很可能已经记录过根因               |
| `lib/index.js`         | 响应出口 238–283、`registerRoute` 440–477 | 区分 400/404/500 是谁发的                |
| `lib/index.js`         | 相关路由 542–1497                         | 看参数钳制与副作用排序                   |
| `CONVENTIONS.md`       | §3.5 错误处理、§5 路由契约                | 判断"这是不是故意这么写的"               |

## 步骤

1. **先复现，写下最小复现路径**：一条命令、一次点击、一个请求体。
   不能复现就停下来，把"复现失败"和已尝试的输入写进交付说明，不要盲改。
2. **定位层**：前端（`assets/`）、路由/编排（`lib/index.js`）、数据/算法（`lib/store.mjs`、
   `lib/schedule.mjs`、`lib/dict.mjs`）。判据：网络面板有请求 → 前端是受害者；
   请求返回 4xx/5xx → 路由层；返回 200 但数据不对 → 数据层。
3. **写一条会红的回归**：放 `scripts/test-*.mjs`（端到端）或 `tests/`（单测）。
   断言要精确到"哪个值错了"，例如 `assert.equal(states.receptive.state, 2, '评分 Good 后应进入复习态')`。
   先跑一次确认它是红的（把红的原因写进交付说明）。
4. **改最小面积**：只动导致错误的那个判断；不顺手重构、不批量改注释、不重排 import。
   如果根因是"两个地方逻辑不一致"，两处一起改，并在注释里写明另一处的位置。
5. **跑验证**（见下），红了就回第 4 步。
6. 在交付说明里写**根因**（为什么错）和**为什么之前没测到**（测试盲区在哪）。

## 硬约束

- 不许为了过测试改断言（除非断言本身写错了，要说明原断言错在哪）。
- 不许碰 `data/`、真实 `$DSH_HOME/dsh-word-learn/user.db`；写库测试必须临时 `DSH_HOME`。
- 不许加 `eslint-disable`；不许调大 `CODE_BUDGET`。
- 不许改 `DESIGN.md` 的历史结论；不许引入新依赖；不许加构建步骤。
- 修前端还要说明生效方式：`wordcard`/`annotate` 硬刷新，`dashboard` 要重新激活插件。

## 必须执行的验证

```bash
pnpm lint:fix
pnpm format
node scripts/test-<相关脚本>.mjs   # 先单跑，失败信息更短
pnpm verify                        # 唯一验收，必须绿
```

前端改动另需（按 README「开发」节）：

```bash
node scripts/test-scope.mjs        # 改划词范围判定时
node scripts/test-annotate.mjs     # 改标注层时
pnpm test:unit                     # 新增单测时
```
